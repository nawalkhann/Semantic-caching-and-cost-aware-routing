Semantic caching and cost-aware model routing for RAG

An open-source Python layer that sits in front of the LLMs in a retrieval-augmented generation (RAG) service. It answers repeat questions from a semantic cache, sends easy questions to a small model and hard ones to a large model, and tracks cost and latency for every request.

Why RAG products get expensive

Every question to a RAG service usually costs one large-model call, priced on the retrieved context plus the answer. Real traffic is repetitive and mostly simple, so much of that spend goes to questions that were already answered, or that a model costing a twentieth as much would answer just as well. This project removes both kinds of waste and measures exactly what that does to quality.

Guarded semantic cache

It reuses an answer when a new question means the same thing. Embedding similarity alone is not enough: "storage on Pro" and "storage on Business" look almost identical. So a hit also needs matching entities and numbers, overlapping topic words, and the same retrieved documents.

Cost-aware router

A logistic complexity score sends simple lookups to a small model. Comparisons, constraint problems and arithmetic go to a large model. It uses only signals that are free before any LLM call: the query text, its entities and the retrieval scores.

Per-request accounting

Every request logs its route, tokens, cost and a latency breakdown (embed, retrieve, cache, LLM) to SQLite. A dashboard shows cumulative cost, rolling p95 latency and the route mix.

The similarity-only cache looks cheapest, but it served the wrong answer on 21% of hits and lost 15.7 accuracy points. The guards bring false hits down to 0.1%. The full analysis and threshold sweeps are on the benchmark page.

Try it

git clone https://github.com/nawalkhann/semantic-caching-and-cost-aware-routing
cd semantic-caching-and-cost-aware-routing
pip install -e ".[dev]"
pytest
python benchmarks/run_benchmark.py
uvicorn ragroute.api:create_app --factory   # then open /dashboard

To use real models, point it at any OpenAI-compatible endpoint with environment variables. The README has the details.
